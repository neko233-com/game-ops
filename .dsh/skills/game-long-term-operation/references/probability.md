# 抽卡与概率（Probability & Gacha Math）

任何有随机性的游戏系统——抽卡、掉落、暴击、技能触发——都必须用**精确有理数**计算概率。`float64` 在多次乘法/幂运算后会漂移；游戏经济是精确的，概率也必须精确。

本 skill 提供的精确概率 API：

| 函数 | 公式 | 用途 |
|---|---|---|
| `num.BinomialP(n, k, p)` | `C(n,k)·p^k·(1-p)^{n-k}` | 多次独立试验中恰好 k 次成功的概率 |
| `num.GeometricP(k, p)` | `(1-p)^{k-1}·p` | 第 k 次才首次成功的概率 |
| `num.Comb(n, k)` / `num.Perm(n, k)` | C(n,k) = n!/(k!(n-k)!) | 组合数 / 排列数，精确整数 |
| `num.Factorial(n)` | n! | 阶乘 |

所有结果都是**精确分数**——分子分母都是 big.Int。CLI `numcalc` 让你在 agent 语境下直接调用。

## 示例：单池保底 SSR 概率

```
SSR 掉率 p = 0.006（精确 = 3/500）
80 抽保底 → 恰好第 80 抽时首次 SSR 的概率？
```

精确值：`GeometricP(80, 3/500) = (497/500)^79 · 3/500`

```sh
go run ./cmd/numcalc geom 80 0.006
# geom(k=80,p=3/500) = 28605172275... (≈ 0.003645)
```

## 示例：3% 暴击率，攻击 10 次至少暴击 2 次

```
至少 2 次 = 1 − (恰好 0 次 + 恰好 1 次)
= 1 − BinomialP(10,0,0.03) − BinomialP(10,1,0.03)
```

```sh
go run ./cmd/numcalc binom 10 0 0.03
go run ./cmd/numcalc binom 10 1 0.03
# 结果 = 1 − 0.737424 − 0.228130 = 0.034446
```

## 精确 vs. float64 的区别

| 计算 | float64 结果 | 精确结果 |
|---|---|---|
| `1 - (0.994)^80` | 0.395346263… | 381344310586… / 5^80（约分后的 exact 分数） |
| `(1/3) * 3` | 0.9999999999999999 | **1** |
| `C(30,10)` | 30045015 | **30045015**（大数无截断） |

游戏抽卡系统必须用精确数做概率计算。Agent 配置抽卡池时应：

1. 把掉率写成精确分数（如 `3/500` 而不是 `0.006`）
2. 用 `numcalc geom` 或 `numcalc binom` 验证保底概率、期望抽数
3. 把期望抽数和 SSR 保底价值（归一化到基准单位后）对齐

## 期望值与价值检验

保底池的期望值：`E = Σ_{k=1}^{cap} k · GeometricP(k, p)`

理想情况：保底 SSR 的**归一化价值** ÷ 期望抽数 ≈ 每抽平均奖励的 20–50×。低于这个阈值玩家会觉得"不值"，高于这个阈值会挤压其他奖励价值。

用 `normalize.Normalize` 把 SSR、其他奖池奖励、每日任务产出、单次抽卡成本都归一到基准单位后，再做期望检验。
