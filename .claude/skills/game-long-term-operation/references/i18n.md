# Multi-language rule (中文优先)

Chinese is the **authoritative, primary language**. It is the default for every
CLI and the docs site, even when the environment locale is something else.
English and Japanese are supported alternatives, not replacements.

## CLI language switching

```sh
# Vercel-style HTML report — default is Chinese; -lang switches
go run ./cmd/htmlreport examples/report.json report.html
go run ./cmd/htmlreport -lang en examples/report.json report-en.html
go run ./cmd/htmlreport -lang ja examples/report.json report-ja.html

# Professional time-to-cap analysis
go run ./cmd/proanalysis                       # 中文
go run ./cmd/proanalysis -lang en -workers 16 # English
go run ./cmd/proanalysis -lang ja -workers 16 # 日本語
```

`i18n.Parse` maps locale strings (`zh-CN`, `en-US`, `ja-JP`, `中文`, `日本語`, …)
to `zh`/`en`/`ja`. **Unknown or empty locales fall back to `zh`**, never to
English. The generated HTML carries `<html lang="...">` matching the selection.

## Catalog conventions

- All display strings live in `i18n/i18n.go` under a key, e.g.
  `section.pillars`, `status.critical`, `conclusion.long`.
- The Chinese entry is the source of truth; add the new key with `en` and `ja`
  translations at the same time.
- `T(lang, key)` falls back to Chinese, then to the key itself, so a missing
  translation is visible rather than silent.
- Exact numeric values (fractions, ratios, metric keys like `retention_d1`)
  are **never translated** — only their labels and explanations are.
- Tests assert that every key exists in all three languages and that a missing
  translation falls back to Chinese.

## Docs site

The Vite+ React site defaults to `zh-CN`, persists the choice in localStorage,
and exposes a topbar switcher `中文 / EN / 日本語` that preserves the current
page route. UI chrome (sidebar groups, prev/next, TOC, copy buttons, loading
text) is translated via `src/i18n/ui.ts`; page content via each page's `i18n`
field. Untranslated blocks are marked with an explicit badge rather than shown
as mixed-language prose. `<html lang>` follows the selection.
